Process note for whoever edits these documents next: PowerShell 5.1's
`Get-Content` / `Set-Content` round trip does NOT preserve non-ASCII in this tree.
It reads a UTF-8 file as cp1252 and re-encodes the resulting mojibake, so every
em dash and section sign in the file doubles. It happened once to
`prompts/PROMPT_EXECUTION_QUEUE.md` during this session and was reversed exactly
(the double-encoded bytes were re-encoded to cp1252 and decoded as UTF-8 again,
verified: 16 em dashes, 24 section signs, zero mojibake, zero replacement chars).
Use the editor tool for these files, or read with `-Encoding UTF8` and write with
`[IO.File]::WriteAllText`. Do not script a whole-file rewrite with `Set-Content`.
