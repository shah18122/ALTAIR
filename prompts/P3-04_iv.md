The card as written was "Jäckel IV solver". Smit added: *consider
Black-Scholes too.* That is a real gap, not a cosmetic one — P3-01 shipped
Black-76 on a forward, and every cash-settled stock and index quote arrives as
a **spot**. Both are in this card because they are the same inversion.

Delivered:

  dividend yield.
* `forward_from_spot`, `forward_delta_to_spot` — the two conversions, named.
* `GreekBasis` — a tag on `Greeks` saying which variable delta differentiates.
* `implied_vol_black76`, `implied_vol_black_scholes`, `iv_uncertainty`.

## 2. THE DECISIONS

**D1 — Black-Scholes is not a second model, and the code says so.**
Substituting `F = S·e^((r−q)T)` into Black-76 reproduces Black-Scholes
exactly; test 2 asserts the prices agree to 1.6e-10 paise. What differs is the
greeks, and mixing the conventions is a live way to mis-hedge:

| | Black-76 (forward) | Black-Scholes (spot) |
|---|---|---|
| delta | 0.545942521 | 0.548325924 |
| ratio | — | ×1.004366 = e^((r−q)T) |
| rho | **−₹38.19** | **+₹1043.44** |

The delta gap is 0.44% — small enough to read as rounding, large enough to
leave a book systematically under-hedged in one direction every day. Rho is
worse: under Black-76 the rate enters *only* the discount factor, so
rho = −T·V and is **negative** for a long call; under Black-Scholes the rate
also drifts the forward, so rho = K·T·e^(−rT)·N(d₂) and is **positive**.
Opposite sign, 27× magnitude. Using one formula on the other basis is not a
rounding error.

**D2 — `GreekBasis` is carried in the struct, and ordinal 0 is
`Unspecified`.** A delta is dimensionless, so the type system cannot catch a
basis mismatch the way it catches `Price * Lots`. Tagging it makes the
mismatch assertable. Ordinal 0 is `Unspecified` deliberately: a
default-constructed `Greeks` must not read as a valid basis. That is the
phantom-default-state defect this repo has now hit five times.

**D3 — Which pricer to use is a question about the INPUT, not a preference.**
A listed future quotes the forward: use `black76`, because the market's own
forward already contains whatever the dividend and repo actually are — one
fewer estimated parameter. A cash index or stock quotes spot: use
`black_scholes` and own the dividend assumption explicitly, rather than
smuggling it into a forward somebody guessed.

**D4 — Safeguarded Newton, and the header says it is not Jäckel.** "Let's Be
Rational" reaches machine precision in two iterations using ~40 hard-coded
rational coefficients. Those coefficients cannot be checked by reading them,
and one mistyped digit yields an IV wrong in the fourth decimal *in one region
of the surface only* — the defect class that survives testing and then
misprices a wing. Newton on the pricer inverts, by construction, the same
function the pricer evaluates; it has no coefficients of its own to get wrong.
Measured: 3–14 iterations, ~1.6 µs per solve. If profiling later puts this on
a hot path, Jäckel can go behind this interface **with this implementation as
the oracle to check it against**.

**D5 — One Black-76 in the codebase.** `detail::black76_unchecked` was
extracted from `black76` so the solver iterates on the *identical* formula
rather than a copy. A solver carrying its own pricer inverts a different model
from the one that quotes, and the two drift apart the first time either is
edited. It also lets the solver keep the forward in `double`: routing it
through integer paise on every step quantises it, and in the wings that is
visible in the answer.

**D6 — Convergence is tested in VOL units, not price units.** *This was a real
defect, caught by the corpus.* The first implementation stopped on a relative
price residual and returned 0.1800001049 for a case whose true vol was 0.18 —
wrong in the seventh decimal. The answer is a vol and the residual is a price;
they are related by vega, which varies four orders of magnitude across a
chain. A deep ITM put worth ₹5,888 has vega 36 paise/vol against an ATM
272,607, so a price-tight answer there is a vol-loose one. Dividing by vega
puts the test in the units of the thing being measured.

The tolerance is also **computed per option, not constant**: price is a
double, so it is known only to ~ε relative, and no solver can resolve vol
finer than that price quantum divided by vega. The floor is
`4·target·ε/vega` — the same error-propagation identity `iv_uncertainty`
exposes to callers, applied to the arithmetic itself.

**D7 — Prices outside the no-arbitrage bounds are refused, including exactly
at them.** Below the discounted intrinsic no σ ≥ 0 exists; at or above the
ceiling (df·F for a call, df·K for a put) only σ = ∞ reaches it. The tempting
answer is the endpoint. Rule 9: a stale, crossed, or wrong-forward quote must
raise, not silently become "zero vol". Puts have a *different* ceiling —
df·K, not df·F — which is invisible when F ≈ K and asserted separately.

**D8 — The error bar is part of the answer.** `ImpliedVol` returns the vega at
the solution, not a bare `Vol`, because IV precision is not uniform across a
surface. Against a 24'080 forward, 30 days, 15 vol, for one 5-paise tick:

| strike | vega | IV uncertainty |
|---|---|---|
| 24000 | 272,607 | 0.000018 vol pts |
| 26000 | 57,967 | 0.000086 vol pts |
| 28000 | 630 | **0.0079 vol pts — 433× the ATM band** |
| 32000 | 0.0001 | **49,427 vol pts** |

Nothing about that last quote looks unusual, and its price carries no
information about vol at all. `iv_uncertainty` returns **+∞** on zero vega
rather than a large finite number, so a caller cannot weight a meaningless
point as merely imprecise (ROADMAP §3).

## 4. ACCEPTANCE TESTS — 8, all passing

1. **round_trip_recovers_the_known_vol** — 10 cases spanning the far wing
   (7 paise), a 2-day weekly, 95 vol, 2 vol, deep ITM puts. All to 1e-9
   relative. Asserts the corpus has not been silently narrowed.
2. **black_scholes_and_black76_are_one_model** — prices agree to 1.6e-10;
   vega identical; delta ratio *is* e^((r−q)T); rho signs differ; basis tags
   set; `Greeks{}.basis == Unspecified`.
3. **refuses_prices_outside_the_no_arbitrage_bounds** — below, exactly at, and
   above both bounds; and prices *just inside* still solve, so the refusals
   cannot pass for a solver that refuses everything.
4. **refuses_degenerate_inputs** — T ≤ 0, non-positive price/forward/strike,
   NaN, and the public wrapper refuses the same things as the internal.
5. **vega_collapse_widens_the_error_bar** — asserts the hazard **exists**
   (wing vega < ATM/100) before asserting it is handled; ∞ on zero vega;
   and measures error propagation by quantising a price and checking the IV
   shift equals dP/vega.
6. **implied_vol_is_monotone_in_price** — 199 probes across the admissible
   range, all solved, strictly increasing. Needs no reference numbers.
7. **a_parity_consistent_pair_implies_one_vol** — the put price is derived
   from **parity alone**, never from the put formula, so it has not touched
   the code path under test. Both legs return 17 vol to 6.8e-15. This is what
   kills a sign error in the put branch.
8. **the_bisection_safeguard_is_exercised_and_bounded** — asserts the
   safeguard branch actually fires (3 of 10 cases), bounds iterations, and
   times it.

## 6. CARRIED FORWARD

* `black_scholes` takes a **continuous dividend yield**. Indian single stocks
  pay lumpy discrete dividends, so for stock options this is an approximation.
  It is the right one for NIFTY/BANKNIFTY. Discrete-dividend handling is a
  P3-03 concern (American exercise is driven by exactly those dividends).
* The solver assumes European exercise. American options must go through
  P3-03 before their IV means anything.
