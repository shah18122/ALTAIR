1. WHAT ALTAIR IS
------------------------------------------------------------------------------
- C++23 trading engine + Qt 6.8 Widgets desktop, one process. The UI cannot
  trade: desktop/ must never link altair_oms or altair_broker, and the link
  line enforces it (altair_desktop_link_audit, "gate 3").
- Broker roles:
    FYERS  = PRIMARY market data (live stream + history) and read-only account.
    Kite   = fallback market data and read-only account.
    Orders = live submission DISABLED by design. Both FYERS and Kite order
             translation sit behind one shared dispatch permit that re-checks
             route, session, risk, transport and kill-switch state
             (oms/tests/test_broker_dispatch_gate.cpp: "live-disabled refuses").
    Paper  = isolated simulated ledger fed by real data where available.
- Anything that touches a socket or a credential is a separate helper process
  in app/ (altair_fyers_login / _account / _history / _webhook / _ticker,
  altair_kite_*). They dry-run by default and need --go to touch the network.
- Directory map (one component, one directory):
    core/        strong units (paise, lots, time), clocks, memory, lock-free
    instruments/ point-in-time contract spec store, NSE/BSE/FYERS masters
    feed/        decoders (Kite, FYERS), normaliser, failover, tick store,
                 source router, FYERS data-socket protocol (NEW)
    book/        L2 book, microstructure, flow
    features/ analytics/ models/ strategies/ risk/ backtest/ flagging/
    oms/         order state, exit ladder, broker adapters behind the permit
    broker/      OAuth, HTTPS client, account snapshots, WebSockets
    app/         helper binaries (network + credentials live here only)
    server/      price bus / price service
    desktop/     the Qt UI
    ops/         runbooks (fyers-webhook, phase8-acceptance, linux-deployment)
    client/      RETIRED web client (kept for reference, not built into UI)

2. AGREED PRODUCT DIRECTION
------------------------------------------------------------------------------
- Keep the C++23 engine and Qt Widgets desktop. Keep the dark colours; improve
  organisation, typography, tables, spacing and top navigation.
- One "Brokers" destination holding FYERS and Zerodha Kite: app ID / API key,
  masked secret and redirect URL entered in-app; browser OAuth; progress,
  validation, connection state, account data and redacted logs shown there.
- Market data preference: FYERS first, eligible Kite connection as fallback.
  Data source and order destination are separate settings with provenance.
- OPEN DECISION (blocks live orders only): the order route default. The request
  said both "FYERS for orders" and "Kite for orders". Both routes exist and are
  configurable; confirm the default before live submission is ever enabled.
- Terminal = open positions across brokers + available funds (total and per
  broker). Order history, credentials and diagnostics live in Brokers.
- Live Grid and Chart removed as UI destinations (their ingestion, datasets,
  replay and computation are kept). Layout button removed; the sidebar resizes
  with the mouse and can be hidden/shown from the keyboard.
- Pair Trading replaces Ratio Spread: choose instrument A and B freely.
  Comparison formulas and entry/exit rules are still TO BE DISCUSSED; nothing
  chooses a hedge ratio or z-score rule silently.
- Every Atlas model has its own page; implementation, training, evaluation and
  live readiness are shown as separate states.
- Continuous cross-exchange and cash/futures opportunity scanning, monitored
  signals and paper execution first. Retail broker streams and licensed MTBT
  are different feeds.
- Credentials are configuration, never source, logs or fixtures. The FYERS app
  secret that was once shared in chat must be rotated before live use.

3. ENGINEERING RULES (a violation fails review)
------------------------------------------------------------------------------
 1. No lot size, tick size, strike step or expiry as a literal -- all come from
    the point-in-time spec store (instruments/).
 2. No double crossing a module boundary carrying money, quantity or time; use
    core/types strong units. Price * Lots must not compile.
 3. All money is integer paise. Doubles only inside analytics.
 4. No heap allocation inside ALTAIR_HOT; no exceptions on the hot path --
    return std::expected.
 5. Every signal is priced net of full cost before it exists.
 6. Backtest and live share one code path: replay and live feeds emit the same
    struct into the same pipeline.
 7. No look-ahead: purged CV with embargo, point-in-time fundamentals,
    strategies read time off the tick, never a wall clock.
 8. The tighter stop is checked before the original stop.
 9. Fail loud rather than trade wrong: ambiguity blocks the symbol and flags.
10. Every live decision is reproducible from
    {model_hash, feature_version, config_hash, spec_version, tick_seqno}.
11. A fixed bound must REFUSE, PROVE unreachable, or TRUNCATE VISIBLY. Silent
    clamps are banned; unavoidable clamps go to the safe side. Enforced at
    configure time by cmake/BoundsAudit.cmake (annotate with "// RULE 11: ...").
Build-time audits that also fail the configure:
  - cmake/NamespaceAudit.cmake: one name per namespace across engine headers
    (the more specific header renames, e.g. HsmError, not Error).
  - desktop link audit: the UI may not link oms/ or broker/.
Process: freeze a task card before coding, build + run acceptance tests after
every change, record evidence (never claim a live result from a unit test).

4. BUILD AND RUN
------------------------------------------------------------------------------
Windows (primary host):
    build.bat net            engine + helpers + desktop (vcpkg: Boost, OpenSSL)
    ctest --preset net       full suite
    Qt 6.8.3 msvc2022_64 (default D:/Qt/6.8.3/msvc2022_64 or ALTAIR_QT_ROOT)
    Desktop: build/net/desktop/altair_desktop.exe
Linux (first compiled here on 2026-09-28; engine + helpers + tests, no UI):
    cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
          -DALTAIR_BUILD_BENCH=OFF -DALTAIR_NATIVE_ARCH=OFF
    ninja -C build && ctest --test-dir build
    needs: g++ 13+, libboost-dev, libssl-dev. The desktop needs Qt >= 6.8.

FYERS end to end (run from the repo root):
    1. altair_fyers_login          OAuth in the browser -> data/fyers_session.json
    2. altair_fyers_account --go   profile, funds, positions, holdings, orders
    3. altair_fyers_history --symbol NSE:NIFTY50-INDEX --from D --to D --go
    4. altair_fyers_ticker --go [--symbols NSE:NIFTY50-INDEX,NSE:SBIN-EQ]
           [--depth] [--lite] [--seconds 60] [--jsonl data/fyers.jsonl]
           [--store data/fyers.ticks]      -> data/fyers_ticks.json
    Desktop: Live Feed page -> "FYERS (primary)" -> Listen.

------------------------------------------------------------------------------

------------------  -----------------------------------------  -------------

                    /api/v3/validate-authcode (appIdHash),
                    /api/v3/validate-refresh-token

                    holdings, orders

Quotes/depth REST   /data/quotes, /data/depth                  not used (socket covers it)

Live data socket, as the official SDK does it:
  - hsm_key read from the access token (JWT) payload; expired token refused.
  - POST /data/symbol-token turns symbols into topics:
      sf|<segment>|<token>  quotes     dp|<segment>|<token>  5-level depth
      if|<segment>|<index name>        (index names from the SDK's own table)
  - Frames: auth (type 1), lite/full mode (12), subscribe/unsubscribe (4/5,
    1500 topics per frame, 5000 per connection), channel pause/resume (7/8),
    ack (3) every N feeds as the server asks, ping [0,1,11] every 10 s.
  - Server data (type 6): snapshot (83), full update (85), lite update (76),
    decoded into exactly the SDK's on_message JSON, then through the existing
    feed/fyers_adapter.hpp into Tick / DepthUpdate, the tick store and
    data/fyers_ticks.json. Bounded reconnect with backoff; Ctrl+C closes cleanly.
  Verification:
    feed/tests/test_fyers_hsm.cpp, 31/31: every frame builder matches the SDK
    byte for byte, and every decoded frame equals the SDK's own output. Golden
    vectors (feed/tests/fyers_hsm_golden.hpp) were produced by running the
    official SDK. Also covered: truncated frames never over-read, and socket
    JSON becomes a Tick at 612.35 through the adapter.
    NOT verified here: a real connection. This cloud sandbox's network policy
    blocks socket.fyers.in, and no FYERS login exists here. Step 1 of
    section 6 closes this.
  Deliberate differences from the SDK:
    - An absent value (-2147483648) is never stored. The SDK stores it for
      index updates because it compares against a string.
    - An unknown topic is counted; the SDK aborts the whole frame.
    - An index with prev_close 0 omits ch/chp; the SDK drops the message.
    - The client name at auth is "AltairCpp-1.0" (override with --source).

10. PHASE 1 -- MAC PORTABILITY (in progress since 2026-09-29)
------------------------------------------------------------------------------
Approach: GitHub-hosted macos-15 runners are arm64 Apple Silicon Macs, and
they are free for this public repo. They provide the native evidence that a
Windows host cannot:
  P1-01 presets    `cmake --preset macos-arm64` configures and compiles on
                   arm64 (Homebrew Boost/OpenSSL). The deployment target was
                   raised from 13.0 to 13.3 because libc++ only ships
                   floating-point std::to_chars from macOS 13.3.
  P1-02 page alloc  page_alloc / arena_pool tests run natively (Darwin mmap).
  P1-03 clock       time / tsc_clock / exchange_ts tests run natively
                    (mach_absolute_time path).
  P1-04 bundle      Qt 6.8.3 (aqtinstall), Altair.app built, installed OUTSIDE
                    the checkout, layout/helpers/frameworks/arch recorded, and
                    launched offscreen for 20 s.
                    Still open: a Finder launch and a real broker-helper run.
  P1-05 MPS         NOT possible on CI runners (no Metal GPU). Needs a real
                    Apple Silicon Mac plus a chosen backend (LibTorch+MPS or
                    Metal); the CPU trainer stays the reference.
  P1-06 go/no-go    written from the CI evidence + P1-05 once measured.
Where to look: Actions tab -> "macOS arm64 (Phase 1)" -> job summary and the
phase1-evidence-engine / phase1-evidence-desktop artifacts.
